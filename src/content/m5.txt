@@lesson Meet pandas: your Search Console export as a table
@@text
**pandas** is the Python library for tables. If you know Excel or Google Sheets, you already understand the ideas:

| Excel | pandas |
|---|---|
| a sheet (table) | a **DataFrame**, usually called `df` |
| one column | a **Series**, e.g. `df["clicks"]` |
| filter | `df[df["clicks"] > 100]` |
| sort | `df.sort_values("clicks")` |
| pivot table | `df.groupby("page")` |
| VLOOKUP | `df.merge(other_table)` |

On your computer or in Colab you read a file with `pd.read_csv("Queries.csv")`. In this course the data is stored as text, and `io.StringIO()` makes the text behave like a file. Here is a tiny example:

@@exercise Totals and overall CTR
Using `df`, store:

- `total_clicks` and `total_impressions`
- `overall_ctr`: the CTR of the whole site, as a fraction
- `n_queries`: how many **different** queries there are

@@starter
total_clicks = None
total_impressions = None

n_queries = None

@@hint
`df["clicks"].sum()` gives total clicks. For the overall CTR, divide total clicks by total impressions. **Don't** take the average of the `ctr` column. For `n_queries`, use `df["query"].nunique()`.

@@solution
total_clicks = df["clicks"].sum()
total_impressions = df["impressions"].sum()
overall_ctr = total_clicks / total_impressions
n_queries = df["query"].nunique()

print(total_clicks, total_impressions, overall_ctr, n_queries)
print(len(df), "rows")

@@tip
The first thing to ask of any AI-written pandas script: **"Print `df.shape` and `df.columns.tolist()` right after loading."** Most AI bugs with exports are about column names: `"CTR"` vs `"ctr"`, `"Top queries"` vs `"query"`, or a space at the end of a name. Also check CTR averages. The **mean of a CTR column** is not the site CTR, because it treats a query with 10 impressions the same as one with 10,000.

@@lesson Filtering rows with conditions
@@text
To filter, put a **condition** inside square brackets: `df[df["impressions"] > 5000]`.

The condition itself is a column of `True` / `False` values, one for each row. pandas keeps the rows that are `True`.

@@example What a condition looks like
high_impressions = df["impressions"] > 5000
print(high_impressions.head())     # True or False for each row

df[high_impressions][["query", "impressions"]]

@@text
To combine conditions, pandas uses **symbols**, not words:

| You mean | Write | Example |
|---|---|---|
| and | `&` | `(df["impressions"] > 5000) & (df["ctr"] < 0.02)` |
| or | `\|` | `(df["position"] <= 3) \| (df["clicks"] > 300)` |
| not | `~` | `~df["query"].str.contains("sweat")` |

**Put brackets around each condition.** Without them, Python gets the order wrong and shows a confusing error.

@@example Two conditions with &
big_and_ranking = df[(df["impressions"] > 10000) & (df["position"] <= 10)]
print(len(big_and_ranking), "rows")
big_and_ranking[["query", "impressions", "position"]]

@@example Text filters: contains, isin and not
blog = df[df["page"].str.contains("/blog/")]
print(len(blog), "rows are blog pages")

branded = df["query"].str.contains("sweat")
non_brand = df[~branded]                      # ~ means "not"
print(len(non_brand), "rows are non-brand")

products = ["https://www.sweatandco.sg/products/spin-bike-s1", "https://www.sweatandco.sg/products/foldable-treadmill-t200"]
df[df["page"].isin(products)][["query", "page", "clicks"]]

@@bug Page-1 queries with a low CTR
The AI wrote this filter for "page-1 queries with a CTR under 2%". It crashes. Read the error, then fix it.

@@code
page1_low_ctr = df[(df["position"] <= 10) and (df["ctr"] < 0.02)]

print(len(page1_low_ctr), "queries need a better snippet")
page1_low_ctr[["query", "position", "ctr"]]

@@hint
In pandas filters, the word `and` doesn't work. Which symbol means "and"?

@@solution
page1_low_ctr = df[(df["position"] <= 10) & (df["ctr"] < 0.02)]

print(len(page1_low_ctr), "queries need a better snippet")
page1_low_ctr[["query", "position", "ctr"]]

@@explain
`and` works on **one** True/False value. A pandas condition is a whole **column** of True/False values, so Python asks "is this whole column True?" and can't answer. That is the "truth value of a Series is ambiguous" error. `&` compares row by row. Keep the brackets around each condition.

@@check
ref = pd.read_csv(io.StringIO(GSC_CSV))
want = ref[(ref["position"] <= 10) & (ref["ctr"] < 0.02)]
assert len(page1_low_ctr) == len(want), f"Expected {len(want)} rows."
assert sorted(page1_low_ctr["query"]) == sorted(want["query"]), "Not the right rows yet."

@@tip
When AI writes a filter, ask it to **print the number of rows before and after each filter**. If a filter keeps 0 rows or all rows, something is wrong, very often a fraction vs percentage mix-up (`ctr < 2` keeps everything). If you see `and` / `or` in a pandas filter, that is the bug from this lesson.

@@lesson groupby: summarise like a pivot table
@@text
`groupby` works like a pivot table: put rows into groups, then calculate something for each group.

`df.groupby("page")[["clicks", "impressions"]].sum()` means: "for each page, add up clicks and impressions".

**Important:** after grouping, **calculate CTR again** from the summed clicks and impressions. Don't add up or average the `ctr` column.

@@example Clicks and impressions per page
by_page = df.groupby("page")[["clicks", "impressions"]].sum()
by_page["ctr"] = by_page["clicks"] / by_page["impressions"]

by_page.sort_values("impressions", ascending=False)

@@text
`.agg()` lets you make several summaries at once, each with its own name. `reset_index()` turns the group names back into a normal column, which is easier for merging and exporting.

@@example Several summaries with agg
by_page = df.groupby("page").agg(
    queries=("query", "count"),
    clicks=("clicks", "sum"),
    impressions=("impressions", "sum"),
    best_position=("position", "min"),
).reset_index()

by_page.sort_values("clicks", ascending=False).head(6)

@@text
groupby also finds **keyword cannibalisation**: one query where more than one of your pages gets impressions.

@@example Queries with more than one page
pages_per_query = df.groupby("query")["page"].nunique()
cannibal = pages_per_query[pages_per_query > 1]
print(cannibal)

df[df["query"].isin(cannibal.index)][["query", "page", "impressions", "position"]]

`merge` works like VLOOKUP: it joins two tables on a shared column. Here you'll add Ahrefs search volume and keyword difficulty (KD) to the Search Console data.

@@text
To merge, both tables need a column with the **same name** and the **same values**. Rename the Ahrefs columns first. Use `how="left"` to keep **every** Search Console row, even when Ahrefs has no data for it.

Check the shape **before and after**. A left merge should never add rows. If it does, the other table has duplicates.

@@example A first merge
kw = pd.read_csv(io.StringIO(AHREFS_CSV))
kw = kw.rename(columns={"Keyword": "query", "Volume": "volume", "KD": "kd"})

print("Before:", df.shape)
merged = df.merge(kw, on="query", how="left")
print("After: ", merged.shape)    # more rows than before?!
print("Missing volume:", merged["volume"].isna().sum(), "rows")

@@text
The table got **one row longer**, with no error. That is because `yoga mat singapore` is in the Ahrefs export **twice** (it was exported from two keyword lists). The merge matched it twice and copied the Search Console row. Now its clicks would be counted twice in any total.

The fix: remove duplicates before merging, with `drop_duplicates(subset="query")`.

`NaN` means "no value". Rows with `NaN` volume are queries Ahrefs didn't have. That is normal, but count them, so you know how much is missing.
