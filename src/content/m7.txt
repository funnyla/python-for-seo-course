@@lesson What an API is, and how to read JSON
@@text
An **API** is a way for one program to ask another service for data. Think of a restaurant: you don't walk into the kitchen. You order from a menu, and the waiter brings back your food. With an API:

1. **You send a request**: what you want (for example "clicks by query for October") plus a key or login that proves you are allowed.
2. **The service sends back a response**, usually in a text format called **JSON**.

JSON looks almost exactly like Python **dictionaries** (`{ }`) and **lists** (`[ ]`), nested inside each other. A Search Console API response looks like this:

```
{
  "rows": [
    {"keys": ["yoga mat singapore", "https://www.sweatandco.sg/collections/yoga-mats"],
     "clicks": 310, "impressions": 12600, "ctr": 0.0246, "position": 3.9},
    ...
  ]
}
```

To read it: `data["rows"]` is a **list** of rows. Each row is a **dict**. `row["keys"]` is a **list** whose order matches the dimensions you asked for (here: query, then page).

`json.loads()` turns JSON text into Python. A sample response is loaded as the text `GSC_RESPONSE`.

@@example Walking through a response
import json

data = json.loads(GSC_RESPONSE)
print(type(data))
print(data.keys())
print(len(data["rows"]), "rows")

first = data["rows"][0]
print(first)
print("Query:", first["keys"][0])
print("Page: ", first["keys"][1])
print("Clicks:", first["clicks"])

@@lesson From JSON to a DataFrame
@@text
To analyse API data, turn it into a pandas DataFrame. The clearest way: loop through the rows, build one dictionary per row with **named** columns, then call `pd.DataFrame()` on the list.

@@example Rows to a DataFrame
import json
import pandas as pd

data = json.loads(GSC_RESPONSE)

rows = []
for r in data["rows"]:
    rows.append({
        "query": r["keys"][0],
        "page": r["keys"][1],
        "clicks": r["clicks"],
        "impressions": r["impressions"],
        "ctr": r["ctr"],
        "position": r["position"],
    })

api_df = pd.DataFrame(rows)
print(api_df.shape)
api_df.head()

@@text

@@example json_normalize

@@lesson Dates: "last 28 days" done right
@@text
Python's `datetime` module handles dates. `date(2026, 11, 13)` makes a date, and `timedelta(days=3)` is a length of time you can add or subtract.

Two Search Console facts matter here:

1. Data is **delayed**. The most recent 2–3 days are usually missing or incomplete, so reports often end a few days before today.
2. "Last 28 days" means **28 days including both the start day and the end day**. So `start = end - 27 days`, not 28.

To keep results the same every day, this course uses a fixed "today". In a real script, use `date.today()`.

@@example The last 28 days
from datetime import date, timedelta

today = date(2026, 11, 13)          # in a real script: date.today()
end = today - timedelta(days=3)     # Search Console data lags a few days
start = end - timedelta(days=27)    # 28 days, counting both start and end

print(start, "to", end)
print((end - start).days + 1, "days")
print(start.isoformat())            # "YYYY-MM-DD", the format the API wants
print(start.strftime("%d %b %Y"))   # a friendlier format for reports

@@lesson API keys, and the real Search Console API
@@text
An **API key** (or a service account file) works like a password. Anyone who has it can use your account, and you may pay for what they use.

- **Never** put a key straight into your code, a Google Sheet, a Slack message or a GitHub repository.
- In Colab, use **Secrets**: click the key icon in the left sidebar, add a name (for example `ANTHROPIC_API_KEY`) and the value, and switch on "Notebook access". Your code reads it with `userdata.get("NAME")`.
- If a key ever leaks, **revoke it and create a new one immediately**. Deleting the message or the commit is not enough.

@@text
### Setting up the Search Console API (one time)
1. In [Google Cloud Console](https://console.cloud.google.com/), create a project and enable the **Google Search Console API**.
2. Create a **service account**, then create a **JSON key** for it and download the file.
3. In Search Console, open your property → **Settings → Users and permissions** → add the service account's email address. "Restricted" permission is enough for reading data.
4. In Colab, add a secret called `GSC_SERVICE_ACCOUNT` and paste the **whole contents** of the JSON file as its value.

The API wants a request **body**: a dictionary with the dates, dimensions and row limit. Building it with a function makes it easy to reuse.

@@colab Pull 28 days of query + page data from Search Console
This is real code for Colab. Change `SITE_URL` to your property: `sc-domain:yourdomain.com` for a Domain property, or the full URL with a trailing slash (`https://www.yourdomain.com/`) for a URL-prefix property.

@@code
!pip install --quiet google-api-python-client google-auth

import json
from datetime import date, timedelta
import pandas as pd
from google.colab import userdata
from google.oauth2 import service_account
from googleapiclient.discovery import build

SITE_URL = "sc-domain:example.com"      # change this to your property

info = json.loads(userdata.get("GSC_SERVICE_ACCOUNT"))
creds = service_account.Credentials.from_service_account_info(
    info, scopes=["https://www.googleapis.com/auth/webmasters.readonly"]
)
service = build("searchconsole", "v1", credentials=creds)

end = date.today() - timedelta(days=3)
start = end - timedelta(days=27)

rows, start_row = [], 0
while True:                              # pagination: keep asking until a page comes back short
    body = {
        "startDate": start.isoformat(),
        "endDate": end.isoformat(),
        "dimensions": ["query", "page"],
        "rowLimit": 25000,
        "startRow": start_row,
    }
    response = service.searchanalytics().query(siteUrl=SITE_URL, body=body).execute()
    batch = response.get("rows", [])
    rows.extend(batch)
    if len(batch) < 25000:
        break
    start_row += 25000

df = pd.DataFrame([{
    "query": r["keys"][0], "page": r["keys"][1], "clicks": r["clicks"],
    "impressions": r["impressions"], "ctr": r["ctr"], "position": r["position"],
} for r in rows])

print(f"{start} to {end}: {len(df)} rows")
df.sort_values("clicks", ascending=False).head(10)

@@text
**Important when you report on this data:** Search Console hides some queries for privacy (anonymised queries). So the query rows **don't add up** to the site's total clicks. To see how much the query rows cover, run a second request with no dimensions (or with only `["date"]`) for the same dates, and compare: query-level clicks ÷ total clicks. Always state that share and the date range in your reports.

@@tip
Before you run AI-written API code, check: **(1)** no key or JSON file is pasted into the code, **(2)** the scope is read-only (`webmasters.readonly`) when you only need to read, **(3)** it paginates, so it doesn't stop at 25,000 rows, **(4)** it prints the date range and row count. If the AI suggests putting the key in the code "just for testing", say no. Test keys leak too.
